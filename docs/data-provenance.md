# Data origin and provenance

Normal's Nike digital twin mixes two kinds of information. They are stored, labelled and displayed separately.

## 1. Public Nike reference data (real, cited, context only)

| Record | Collection | Source | Fields that prove origin |
|---|---|---|---|
| 17 products (name, subtitle, category, GBP list price, style code, product URL) | `reference_products` | nike.com/gb product and category pages, fetched by automated HTTP GET on 2026-10-24 with no bot restriction encountered and no access control bypassed; only items whose text was read **verbatim** were kept | `dataOrigin: "official_public"`, `verification: "verified_verbatim"`, `sourceUrl`, `retrievedAt`, `retrievalMethod` |
| NIKE, Inc. Q1 FY2027 results (revenue, brand/channel/geography splits, gross margin, EPS, USD millions) | `reference_financials` | investors.nike.com press release of 1 Oct 2026, retrieved 2026-10-24 | `dataOrigin`, `sourceUrl`, `retrievedAt`, `relationshipToSimulator: "context_only_not_simulated_revenue"` |

Rules enforced in code and tests:
- `ReferenceProduct` refuses `dataOrigin: "official_public"` unless `verification === "verified_verbatim"`.
- A simulated product copies the public list price only when the reference is verified; otherwise `priceOrigin: "synthetic"`.
- Public image URLs are stored for provenance only; the UI never hotlinks Nike imagery (original category tiles instead).
- Public financials are USD, quarterly, company-wide; simulated revenue is GBP, hourly, for one fictional shop. They are never combined.
- The bundled cache (`src/reference/nike-catalogue.ts`) is the offline fallback; `getReferenceCatalogue()` reports `servedFrom`.

## 2. Synthetic internal operations (simulated, labelled)

Customers, sessions, orders, inventory, campaigns, shipments, reviews, messages, banners. All generated by the
seeded engine or by the demo storefront and stored in `simulated_*` collections. Every canonical event carries
`source: "simulator"`, `provenance.simulated: true`, `provenance.connectorId: "nike_simulator_v1"` and
`ingestMethod: "simulation"` (or `"action_callback"` for partner-executed actions).

Customer identities are fictional (`"Alex K."`-style handles); no real customer, address or payment data exists.
Review and social-mention text is templated.

## 3. Hidden ground truth (private)

`simulator_ground_truth` and `simulator_state.scenarioParams` hold the injected scenario label and mechanistic
parameters. They are excluded from `/api/dev/simulator/state`, `/api/metrics`, all events and all UI payloads;
`tests/simulator/scenarios.test.ts` and `tests/api/routes.test.ts` assert this.

## UI labelling

Every page shows **"Nike — Unaffiliated Simulation"** and the storefront shows "No real purchases". Product
drawers link to the nike.com/gb source and state that stock, sales and reviews are simulated.
